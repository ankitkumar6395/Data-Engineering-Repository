# 📚 1. Study — Theory
 
## 📖 Topic 1: What Is SQL?
 
SQL stands for Structured Query Language. It is used to communicate with relational databases.
 
Data Engineers use SQL to retrieve, insert, update, delete, and transform data.
 
Example:
 
```
SELECT *
FROM employees;
```
 
This query retrieves all columns and rows from the `employees` table.
 
## 🗄️ Topic 2: What Is a Database?
 
A database is an organized collection of data.
 
For example, a company database may contain employee, customer, product, and order information.
 
```
company_db
├── employees
├── customers
├── products
└── orders
```
 
## 📋 Topic 3: Tables, Rows, and Columns
 
A table stores related data in rows and columns.
 
| employee\_id | employee\_name | department | salary |
| ------------ | -------------- | ---------- | ------ |
| 101          | Ankit          | IT         | 50000  |
| 102          | Rahul          | HR         | 42000  |
| 103          | Priya          | Finance    | 55000  |
 
- Table: A collection of related records.
- Row: One complete record.
- Column: One attribute, such as `department`.
- Value: An individual piece of data, such as `50000`.
 
 
## 🧩 Topic 4: SQL Command Categories
 
| Category | Purpose                     | Examples                     |
| -------- | --------------------------- | ---------------------------- |
| DDL      | Defines database structures | `CREATE`, `ALTER`, `DROP`    |
| DML      | Modifies data               | `INSERT`, `UPDATE`, `DELETE` |
| DQL      | Retrieves data              | `SELECT`                     |
| DCL      | Controls permissions        | `GRANT`, `REVOKE`            |
| TCL      | Manages transactions        | `COMMIT`, `ROLLBACK`         |
 
## 🚀 Topic 5: Why SQL Is Important for Data Engineers
 
SQL helps Data Engineers work with data stored in databases and data warehouses.
 
Common uses include:
 
- Extracting data from source tables.
- Transforming data into useful formats.
- Checking data quality.
- Loading data into target tables.
- Preparing datasets for analytics.

## 2. 📚 Study — Theory
 
### 🗄️ What is a database?
 
A database is an organized collection of data. For example, a company database might store employee details, department information, and project records.
 
```
CREATE DATABASE company_db;
```
 
This creates a database named `company_db`.
 
### 🧩 What is a schema?
 
A schema organizes database objects, such as tables and views.
 
MySQL note: In MySQL, `SCHEMA` and `DATABASE` are synonyms. You can use either term in statements such as `CREATE SCHEMA` and `CREATE DATABASE`.
 
```
CREATE SCHEMA company_db;
```
 
Use either the database or schema creation statement—not both with the same name unless you intentionally choose different names.
 
### 📋 What is a table?
 
A table stores related data in rows and columns.
 
Example: `employees`
 
| employee\_id | employee\_name | department |
| ------------ | -------------- | ---------- |
| 101          | Rahul          | IT         |
| 102          | Priya          | HR         |
| 103          | Aman           | Finance    |
 
- Row: One complete record, such as Rahul’s details.
- Column: One attribute, such as `employee_name`.
- Table: A collection of related records.
- Database: A container for related database objects.
 
 
### 🎯 Why does a Data Engineer need these concepts?
 
Data Engineers organize incoming data into databases and tables so it can be stored, queried, and used by analytics systems. A clear structure makes data easier to manage and understand.
 
### 🔍 Useful MySQL commands
 
| Command             | Purpose                              |
| ------------------- | ------------------------------------ |
| `CREATE DATABASE`   | Create a database                    |
| `SHOW DATABASES`    | List databases                       |
| `USE`               | Select a database                    |
| `CREATE TABLE`      | Create a table                       |
| `SHOW TABLES`       | List tables in the selected database |
| `DESCRIBE`          | Inspect a table's columns and types  |
| `SELECT DATABASE()` | Show the currently selected database |
| `DROP TABLE`        | Delete a table and its data          |
 
⚠️ `DROP TABLE` permanently removes the table and its data. Use it carefully.

## 2. 📚 Study — Theory
 
### 🔢 Numeric data types
 
| Data type      | Use                        | Example      |
| -------------- | -------------------------- | ------------ |
| `TINYINT`      | Small whole numbers        | `1`          |
| `INT`          | Whole numbers              | `1250`       |
| `BIGINT`       | Very large whole numbers   | `9000000000` |
| `DECIMAL(p,s)` | Exact decimal values       | `1250.75`    |
| `FLOAT`        | Approximate decimal values | `3.14`       |
 
💡 Important: Use `DECIMAL` for financial amounts when exact decimal representation matters. `FLOAT` is approximate and is better suited to values where small rounding differences are acceptable.
 
### 📝 Text data types
 
| Data type    | Use                  | Example             |
| ------------ | -------------------- | ------------------- |
| `CHAR(n)`    | Fixed-length text    | `'IN'`              |
| `VARCHAR(n)` | Variable-length text | `'Muzaffarnagar'`   |
| `TEXT`       | Longer text          | Product description |
 
Use `VARCHAR` for values such as email addresses, city names, and product names.
 
### 📅 Date and time data types
 
| Data type   | Stores                                                   | Example                 |
| ----------- | -------------------------------------------------------- | ----------------------- |
| `DATE`      | Date only                                                | `'2026-10-14'`          |
| `TIME`      | Time only                                                | `'14:30:00'`            |
| `DATETIME`  | Date and time                                            | `'2026-10-14 14:30:00'` |
| `TIMESTAMP` | Date and time with time-zone-related conversion behavior | `'2026-10-14 14:30:00'` |
 
`TIMESTAMP` and `DATETIME` behave differently. MySQL converts `TIMESTAMP` values between the session time zone and UTC, while `DATETIME` does not perform that conversion.
 
### 📐 Understanding `DECIMAL(p,s)`
 
In `DECIMAL(8,2)`:
 
- `8` is the maximum number of digits in total.
- `2` is the number of digits after the decimal point.
- Up to six digits can appear before the decimal point.
 
 
For example, `123456.78` fits the definition.
 
### 🧱 What defines a table's structure?
 
A table structure includes:
 
- 📌 Column names
- 🔢 Data types
- 🔒 Constraints such as `NOT NULL`
- 🔑 Keys and other column properties
- ⚙️ Default values
 
 
A well-designed structure helps represent data correctly and prevents unsuitable values from being stored.
 
### 🔍 MySQL commands for examining structure
 
```
DESCRIBE table_name;
```
 
Shows the table's columns and their properties.
 
```
SHOW CREATE TABLE table_name;
```
 
Shows the SQL definition of the table.

## 2. 📚 Study — Theory
 
### 📥 What is `INSERT`?
 
`INSERT` is a SQL data manipulation statement used to add new rows to a table.
 
For example, a Data Engineer may use it to load customer records, product information, or daily operational data into a database.
 
### 🧱 Basic syntax
 
```
INSERT INTO table_name (column1, column2)
VALUES (value1, value2);
```
 
- `INSERT INTO` identifies the target table.
- The column list specifies where values should be stored.
- `VALUES` supplies the data for the new row.
 
 
### 📋 Important rules
 
1. 🔢 Values must be compatible with their column data types.
2. 🧩 The number of supplied values must match the number of specified columns.
3. 📝 Text values are generally enclosed in single quotes.
4. 🔢 Numeric values are generally written without quotes.
5. 📅 Dates should use a suitable format, commonly `'YYYY-MM-DD'`.
6. 🚫 A required column without a default value must receive a value when inserting a row.
7. 🔑 Primary key values must be unique unless the column generates them automatically.
 
 
### 📦 Inserting multiple rows
 
Multiple records can be inserted in a single statement. This is often more convenient than executing a separate statement for every record.
 
### ⚠️ Common mistakes
 
- ❌ Supplying values in the wrong column order.
- ❌ Providing fewer or more values than the column list requires.
- ❌ Inserting text that exceeds a column's allowed length.
- ❌ Duplicating a primary key.
- ❌ Using a database that does not contain the intended table.

## 2. 📚 Study — Theory
 
### 🔍 What is `SELECT`?
 
`SELECT` is a SQL statement used to retrieve data from one or more database tables.
 
Data Engineers use it to inspect loaded data, validate records, prepare reports, and supply data for downstream transformations.
 
### 📋 Retrieve all columns
 
The asterisk (`*`) represents all columns in the selected table.
 
Use it when you need to inspect an entire table during development or debugging.
 
### 🎯 Retrieve specific columns
 
You can specify only the columns needed for a task. This makes results easier to read and can reduce unnecessary data transfer, especially when tables contain many columns.
 
### 🏷️ Column aliases
 
An alias gives a column or calculated expression a temporary heading in the query result.
 
For example, a technical column name can be displayed with a more descriptive report heading. An alias does not rename the original table column.
 
### 🧮 Calculated expressions
 
A query can calculate a value while retrieving data. For example, it can multiply a quantity by a unit cost to display a line total.
 
The calculation appears in the result without requiring a new physical column in the table.
 
### 📊 Query result basics
 
A `SELECT` query returns a result set containing the requested columns and matching rows. Without an explicit sorting instruction, you should not rely on a particular row order.
 
### ⚠️ Common mistakes
 
- ❌ Misspelling a column name.
- ❌ Selecting from the wrong database or table.
- ❌ Forgetting a comma between selected columns.
- ❌ Using an ambiguous column reference in a more complex query.
- ❌ Assuming the displayed row order is guaranteed without `ORDER BY`.

## 2. 📚 Study — Theory
 
### 🔍 What is the `WHERE` clause?
 
The `WHERE` clause filters rows based on a condition. Only rows for which the condition evaluates to true are returned by a `SELECT` query.
 
Data Engineers use filtering to inspect particular records, validate data, and extract subsets of large datasets for further processing.
 
### ⚖️ Comparison operators
 
| Operator | Meaning                          |
| -------- | -------------------------------- |
| `=`      | Equal to                         |
| `<>`     | Not equal to                     |
| `!=`     | Not equal to; supported by MySQL |
| `>`      | Greater than                     |
| `<`      | Less than                        |
| `>=`     | Greater than or equal to         |
| `<=`     | Less than or equal to            |
 
### 📝 Filtering different data types
 
- 🔢 Numbers: Compare values such as quantities or measurements.
- 📝 Text: Match a specific category or name. Text comparisons can depend on the column's collation.
- 📅 Dates: Select records by comparing date values.
- ☑️ Boolean-like values: MySQL commonly represents `TRUE` and `FALSE` as `1` and `0`.
 
 
### 🧠 How filtering works
 
MySQL evaluates the condition for each candidate row. Rows that satisfy the condition are returned; rows that do not satisfy it are excluded.
 
### ⚠️ Important: Handling `NULL`
 
`NULL` represents a missing or unknown value. It should not be tested using ordinary equality or inequality operators. Use `IS NULL` or `IS NOT NULL` when you learn null filtering.
 
### 🚫 Common mistakes
 
- ❌ Using quotation marks incorrectly around text values.
- ❌ Comparing a date or number using an unsuitable format.
- ❌ Forgetting the condition after `WHERE`.
- ❌ Assuming `NULL` behaves like zero or an empty string.
- ❌ Using the wrong comparison operator.

# 📘 Day 7 — AND, OR, NOT: Combining SQL Conditions
 
## 🛠️ 1. Tools Used
 
- 🐬 MySQL Server — stores and processes data.
- 🖥️ MySQL Workbench — write and execute SQL queries.
- 📝 Obsidian — save your notes and track progress.
 
 
***
 
## 📚 2. Study — Theory
 
### 🔹 What are `AND`, `OR`, and `NOT`?
 
These logical operators let you combine or reverse conditions in a SQL `WHERE` clause.
 
| Operator | Purpose                             | Example                                  |
| -------- | ----------------------------------- | ---------------------------------------- |
| `AND`    | All conditions must be true         | Status is `Active` AND score is above 80 |
| `OR`     | At least one condition must be true | Region is `North` OR region is `West`    |
| `NOT`    | Reverses a condition                | NOT status is `Completed`                |
 
### 🟢 A. `AND` operator
 
Use `AND` when a record must satisfy every condition.
 
```
SELECT *
FROM training_applicants
WHERE assessment_score >= 80
  AND experience_years >= 1;
```
 
Meaning: Return applicants who scored at least 80 and have at least one year of experience.
 
### 🔵 B. `OR` operator
 
Use `OR` when a record can satisfy either condition.
 
```
SELECT *
FROM training_applicants
WHERE preferred_shift = 'Morning'
   OR preferred_shift = 'Evening';
```
 
Meaning: Return applicants who prefer either the morning or evening shift.
 
### 🟠 C. `NOT` operator
 
Use `NOT` to reverse a condition.
 
```
SELECT *
FROM training_applicants
WHERE NOT application_status = 'Rejected';
```
 
Meaning: Return applicants whose status is not `Rejected`. Be aware that rows with `NULL` status will not appear in this result.
 
An equivalent form for this particular condition is:
 
```
SELECT *
FROM training_applicants
WHERE application_status <> 'Rejected';
```
 
### 🧠 D. Combining multiple operators
 
You can combine `AND`, `OR`, and `NOT` in one query.
 
```
SELECT *
FROM training_applicants
WHERE assessment_score >= 75
  AND (
	  preferred_shift = 'Morning'
	  OR preferred_shift = 'Evening'
  )
  AND NOT application_status = 'Rejected';
```
 
This returns applicants who meet all of these requirements:
 
- Score is at least 75.
- Preferred shift is Morning or Evening.
- Application status is not Rejected.
 
 
Important: Use parentheses to make the intended logic clear. SQL evaluates `AND` before `OR`, so parentheses can change the result.
 
### ⚠️ E. Common mistakes
 
- Using `AND` when you mean `OR`.
- Forgetting parentheses when mixing operators.
- Using `= NULL` instead of `IS NULL`.
- Assuming `NOT` includes rows with `NULL` values. SQL's treatment of `NULL` requires special care.

## 📚 2. Study — Theory
 
### 🔹 What is `UPDATE` in SQL?
 
The `UPDATE` statement modifies existing values in one or more rows of a database table.
 
For example, a data engineer might need to correct a delivery status, update a product's storage location, or mark a data processing job as completed.
 
Basic syntax:
 
```
UPDATE table_name
SET column_name = new_value
WHERE condition;
```
 
- `UPDATE` — specifies the table to modify.
- `SET` — defines the new value.
- `WHERE` — identifies the rows to modify.
 
 
### 🟢 A. Update one record
 
Suppose a warehouse changes the storage location of a product.
 
```
UPDATE warehouse_bins
SET bin_location = 'B-204'
WHERE bin_id = 101;
```
 
Only the row with `bin_id = 101` is updated, assuming `bin_id` uniquely identifies that row.
 
### 🔵 B. Update multiple columns
 
You can modify several columns in one statement.
 
```
UPDATE warehouse_bins
SET bin_location = 'C-105',
	bin_status = 'Occupied'
WHERE bin_id = 102;
```
 
Both values change for the matching row.
 
### 🟠 C. Update multiple records
 
A single `UPDATE` can modify multiple rows.
 
```
UPDATE warehouse_bins
SET bin_status = 'Inspection Required'
WHERE last_inspection_date < '2026-01-01';
```
 
Every row that satisfies the condition receives the new status.
 
### 🟣 D. Update with multiple conditions
 
Logical operators can be used in an `UPDATE` statement.
 
```
UPDATE warehouse_bins
SET bin_status = 'Priority Inspection'
WHERE bin_status = 'Damaged'
  AND zone_name = 'Cold Storage';
```
 
Only damaged bins in the Cold Storage zone are updated.
 
### 🔴 E. Update using an expression
 
You can calculate a new value using the existing value.
 
```
UPDATE warehouse_bins
SET inspection_count = inspection_count + 1
WHERE bin_id = 103;
```
 
This increases the inspection count by one for the matching row.
 
### ⚠️ F. Why `WHERE` is important
 
Compare these statements:
 
```
-- Updates only the matching row
UPDATE warehouse_bins
SET bin_status = 'Available'
WHERE bin_id = 101;
```
 
```
-- Updates every row in the table
UPDATE warehouse_bins
SET bin_status = 'Available';
```
 
Without `WHERE`, MySQL updates all rows in the table. Before executing an update, verify the target records with a `SELECT` query.
 
```
SELECT *
FROM warehouse_bins
WHERE bin_id = 101;
```
 
### 🛡️ G. Safer updates with transactions
 
For important changes, a transaction lets you review the result before committing it.
 
```
START TRANSACTION;
UPDATE warehouse_bins
SET bin_status = 'Available'
WHERE bin_id = 101;
SELECT *
FROM warehouse_bins
WHERE bin_id = 101;
-- Keep the change:
COMMIT;
-- Or, instead of COMMIT, undo it:
-- ROLLBACK;
```
 
Use `COMMIT` to save the transaction or `ROLLBACK` to undo its uncommitted changes. Transaction behavior depends on the table's storage engine; InnoDB supports transactions.

## 📘 Day 8 — UPDATE: Modifying Existing Data
 
### ❓ 1. What is the purpose of the `UPDATE` statement?
 
The `UPDATE` statement modifies existing values in a database table. It can change one column, multiple columns, or values across multiple rows.
 
### ❓ 2. Can one `UPDATE` statement modify multiple columns?
 
Yes. Multiple assignments can be specified in the `SET` clause.
 
```
UPDATE cloud_resource_costs
SET monthly_cost = 950.00,
	cost_status = 'Verified'
WHERE resource_id = 2;
```
 
### ❓ 3. What happens if an `UPDATE` statement affects no rows?
 
The statement executes, but no records are modified because no rows match the specified condition. This can happen when the identifier does not exist or the filter is too restrictive.
 
### ❓ 4. How can you verify which records will be modified?
 
Run a `SELECT` query using the same `WHERE` condition before executing the update.
 
```
SELECT *
FROM cloud_resource_costs
WHERE cost_status = 'Needs Review';
```
 
### ❓ 5. Can an `UPDATE` statement use arithmetic expressions?
 
Yes. You can calculate a new value using the current column value.
 
```
UPDATE cloud_resource_costs
SET monthly_cost = monthly_cost * 1.05
WHERE resource_id = 1;
```
 
This increases the selected resource's monthly cost by 5%.
 
### ❓ 6. How can you update records using multiple conditions?
 
Use logical operators such as `AND` and `OR` in the `WHERE` clause to identify the intended rows.
 
### ❓ 7. What is the difference between `UPDATE` and `INSERT`?
 
`UPDATE` modifies existing records, while `INSERT` adds new records to a table.
 
### ❓ 8. How can a transaction protect an update operation?
 
A transaction allows you to inspect changes before committing them. If the changes are incorrect and remain uncommitted, you can use `ROLLBACK` to undo them in a transactional storage engine such as InnoDB.
 
### ❓ 9. What should you consider before updating a large table?
 
Check the target rows, verify the filter conditions, consider indexes and transaction size, and understand the impact on concurrent queries. For critical changes, ensure that a recovery plan exists.
 
### ❓ 10. How would you investigate an update that changed unexpected records?
 
Review the executed SQL and its `WHERE` clause, inspect the affected rows, and check whether the update ran inside a transaction. If the changes are still uncommitted, use `ROLLBACK` when appropriate. If they have already been committed, recovery may require a backup or another approved recovery method
