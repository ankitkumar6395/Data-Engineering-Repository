# 📚 1. Study — Theory
 
## 📖 Topic 1: What Is SQL?
 
SQL stands for Structured Query Language. It is used to communicate with relational databases.
 
Data Engineers use SQL to retrieve, insert, update, delete, and transform data.
 
Example:
 
```
SELECT *
FROM employees;
```
 
This query retrieves all columns and rows from the `employees` table.
 
## 🗄️ Topic 2: What Is a Database?
 
A database is an organized collection of data.
 
For example, a company database may contain employee, customer, product, and order information.
 
```
company_db
├── employees
├── customers
├── products
└── orders
```
 
## 📋 Topic 3: Tables, Rows, and Columns
 
A table stores related data in rows and columns.
 
| employee\_id | employee\_name | department | salary |
| ------------ | -------------- | ---------- | ------ |
| 101          | Ankit          | IT         | 50000  |
| 102          | Rahul          | HR         | 42000  |
| 103          | Priya          | Finance    | 55000  |
 
- Table: A collection of related records.
- Row: One complete record.
- Column: One attribute, such as `department`.
- Value: An individual piece of data, such as `50000`.
 
 
## 🧩 Topic 4: SQL Command Categories
 
| Category | Purpose                     | Examples                     |
| -------- | --------------------------- | ---------------------------- |
| DDL      | Defines database structures | `CREATE`, `ALTER`, `DROP`    |
| DML      | Modifies data               | `INSERT`, `UPDATE`, `DELETE` |
| DQL      | Retrieves data              | `SELECT`                     |
| DCL      | Controls permissions        | `GRANT`, `REVOKE`            |
| TCL      | Manages transactions        | `COMMIT`, `ROLLBACK`         |
 
## 🚀 Topic 5: Why SQL Is Important for Data Engineers
 
SQL helps Data Engineers work with data stored in databases and data warehouses.
 
Common uses include:
 
- Extracting data from source tables.
- Transforming data into useful formats.
- Checking data quality.
- Loading data into target tables.
- Preparing datasets for analytics.

## 2. 📚 Study — Theory
 
### 🗄️ What is a database?
 
A database is an organized collection of data. For example, a company database might store employee details, department information, and project records.
 
```
CREATE DATABASE company_db;
```
 
This creates a database named `company_db`.
 
### 🧩 What is a schema?
 
A schema organizes database objects, such as tables and views.
 
MySQL note: In MySQL, `SCHEMA` and `DATABASE` are synonyms. You can use either term in statements such as `CREATE SCHEMA` and `CREATE DATABASE`.
 
```
CREATE SCHEMA company_db;
```
 
Use either the database or schema creation statement—not both with the same name unless you intentionally choose different names.
 
### 📋 What is a table?
 
A table stores related data in rows and columns.
 
Example: `employees`
 
| employee\_id | employee\_name | department |
| ------------ | -------------- | ---------- |
| 101          | Rahul          | IT         |
| 102          | Priya          | HR         |
| 103          | Aman           | Finance    |
 
- Row: One complete record, such as Rahul’s details.
- Column: One attribute, such as `employee_name`.
- Table: A collection of related records.
- Database: A container for related database objects.
 
 
### 🎯 Why does a Data Engineer need these concepts?
 
Data Engineers organize incoming data into databases and tables so it can be stored, queried, and used by analytics systems. A clear structure makes data easier to manage and understand.
 
### 🔍 Useful MySQL commands
 
| Command             | Purpose                              |
| ------------------- | ------------------------------------ |
| `CREATE DATABASE`   | Create a database                    |
| `SHOW DATABASES`    | List databases                       |
| `USE`               | Select a database                    |
| `CREATE TABLE`      | Create a table                       |
| `SHOW TABLES`       | List tables in the selected database |
| `DESCRIBE`          | Inspect a table's columns and types  |
| `SELECT DATABASE()` | Show the currently selected database |
| `DROP TABLE`        | Delete a table and its data          |
 
⚠️ `DROP TABLE` permanently removes the table and its data. Use it carefully.

## 2. 📚 Study — Theory
 
### 🔢 Numeric data types
 
| Data type      | Use                        | Example      |
| -------------- | -------------------------- | ------------ |
| `TINYINT`      | Small whole numbers        | `1`          |
| `INT`          | Whole numbers              | `1250`       |
| `BIGINT`       | Very large whole numbers   | `9000000000` |
| `DECIMAL(p,s)` | Exact decimal values       | `1250.75`    |
| `FLOAT`        | Approximate decimal values | `3.14`       |
 
💡 Important: Use `DECIMAL` for financial amounts when exact decimal representation matters. `FLOAT` is approximate and is better suited to values where small rounding differences are acceptable.
 
### 📝 Text data types
 
| Data type    | Use                  | Example             |
| ------------ | -------------------- | ------------------- |
| `CHAR(n)`    | Fixed-length text    | `'IN'`              |
| `VARCHAR(n)` | Variable-length text | `'Muzaffarnagar'`   |
| `TEXT`       | Longer text          | Product description |
 
Use `VARCHAR` for values such as email addresses, city names, and product names.
 
### 📅 Date and time data types
 
| Data type   | Stores                                                   | Example                 |
| ----------- | -------------------------------------------------------- | ----------------------- |
| `DATE`      | Date only                                                | `'2026-10-14'`          |
| `TIME`      | Time only                                                | `'14:30:00'`            |
| `DATETIME`  | Date and time                                            | `'2026-10-14 14:30:00'` |
| `TIMESTAMP` | Date and time with time-zone-related conversion behavior | `'2026-10-14 14:30:00'` |
 
`TIMESTAMP` and `DATETIME` behave differently. MySQL converts `TIMESTAMP` values between the session time zone and UTC, while `DATETIME` does not perform that conversion.
 
### 📐 Understanding `DECIMAL(p,s)`
 
In `DECIMAL(8,2)`:
 
- `8` is the maximum number of digits in total.
- `2` is the number of digits after the decimal point.
- Up to six digits can appear before the decimal point.
 
 
For example, `123456.78` fits the definition.
 
### 🧱 What defines a table's structure?
 
A table structure includes:
 
- 📌 Column names
- 🔢 Data types
- 🔒 Constraints such as `NOT NULL`
- 🔑 Keys and other column properties
- ⚙️ Default values
 
 
A well-designed structure helps represent data correctly and prevents unsuitable values from being stored.
 
### 🔍 MySQL commands for examining structure
 
```
DESCRIBE table_name;
```
 
Shows the table's columns and their properties.
 
```
SHOW CREATE TABLE table_name;
```
 
Shows the SQL definition of the table.

## 2. 📚 Study — Theory
 
### 📥 What is `INSERT`?
 
`INSERT` is a SQL data manipulation statement used to add new rows to a table.
 
For example, a Data Engineer may use it to load customer records, product information, or daily operational data into a database.
 
### 🧱 Basic syntax
 
```
INSERT INTO table_name (column1, column2)
VALUES (value1, value2);
```
 
- `INSERT INTO` identifies the target table.
- The column list specifies where values should be stored.
- `VALUES` supplies the data for the new row.
 
 
### 📋 Important rules
 
1. 🔢 Values must be compatible with their column data types.
2. 🧩 The number of supplied values must match the number of specified columns.
3. 📝 Text values are generally enclosed in single quotes.
4. 🔢 Numeric values are generally written without quotes.
5. 📅 Dates should use a suitable format, commonly `'YYYY-MM-DD'`.
6. 🚫 A required column without a default value must receive a value when inserting a row.
7. 🔑 Primary key values must be unique unless the column generates them automatically.
 
 
### 📦 Inserting multiple rows
 
Multiple records can be inserted in a single statement. This is often more convenient than executing a separate statement for every record.
 
### ⚠️ Common mistakes
 
- ❌ Supplying values in the wrong column order.
- ❌ Providing fewer or more values than the column list requires.
- ❌ Inserting text that exceeds a column's allowed length.
- ❌ Duplicating a primary key.
- ❌ Using a database that does not contain the intended table.

## 2. 📚 Study — Theory
 
### 🔍 What is `SELECT`?
 
`SELECT` is a SQL statement used to retrieve data from one or more database tables.
 
Data Engineers use it to inspect loaded data, validate records, prepare reports, and supply data for downstream transformations.
 
### 📋 Retrieve all columns
 
The asterisk (`*`) represents all columns in the selected table.
 
Use it when you need to inspect an entire table during development or debugging.
 
### 🎯 Retrieve specific columns
 
You can specify only the columns needed for a task. This makes results easier to read and can reduce unnecessary data transfer, especially when tables contain many columns.
 
### 🏷️ Column aliases
 
An alias gives a column or calculated expression a temporary heading in the query result.
 
For example, a technical column name can be displayed with a more descriptive report heading. An alias does not rename the original table column.
 
### 🧮 Calculated expressions
 
A query can calculate a value while retrieving data. For example, it can multiply a quantity by a unit cost to display a line total.
 
The calculation appears in the result without requiring a new physical column in the table.
 
### 📊 Query result basics
 
A `SELECT` query returns a result set containing the requested columns and matching rows. Without an explicit sorting instruction, you should not rely on a particular row order.
 
### ⚠️ Common mistakes
 
- ❌ Misspelling a column name.
- ❌ Selecting from the wrong database or table.
- ❌ Forgetting a comma between selected columns.
- ❌ Using an ambiguous column reference in a more complex query.
- ❌ Assuming the displayed row order is guaranteed without `ORDER BY`.

## 2. 📚 Study — Theory
 
### 🔍 What is the `WHERE` clause?
 
The `WHERE` clause filters rows based on a condition. Only rows for which the condition evaluates to true are returned by a `SELECT` query.
 
Data Engineers use filtering to inspect particular records, validate data, and extract subsets of large datasets for further processing.
 
### ⚖️ Comparison operators
 
| Operator | Meaning                          |
| -------- | -------------------------------- |
| `=`      | Equal to                         |
| `<>`     | Not equal to                     |
| `!=`     | Not equal to; supported by MySQL |
| `>`      | Greater than                     |
| `<`      | Less than                        |
| `>=`     | Greater than or equal to         |
| `<=`     | Less than or equal to            |
 
### 📝 Filtering different data types
 
- 🔢 Numbers: Compare values such as quantities or measurements.
- 📝 Text: Match a specific category or name. Text comparisons can depend on the column's collation.
- 📅 Dates: Select records by comparing date values.
- ☑️ Boolean-like values: MySQL commonly represents `TRUE` and `FALSE` as `1` and `0`.
 
 
### 🧠 How filtering works
 
MySQL evaluates the condition for each candidate row. Rows that satisfy the condition are returned; rows that do not satisfy it are excluded.
 
### ⚠️ Important: Handling `NULL`
 
`NULL` represents a missing or unknown value. It should not be tested using ordinary equality or inequality operators. Use `IS NULL` or `IS NOT NULL` when you learn null filtering.
 
### 🚫 Common mistakes
 
- ❌ Using quotation marks incorrectly around text values.
- ❌ Comparing a date or number using an unsuitable format.
- ❌ Forgetting the condition after `WHERE`.
- ❌ Assuming `NULL` behaves like zero or an empty string.
- ❌ Using the wrong comparison operator.

# 📘 Day 7 — AND, OR, NOT: Combining SQL Conditions
 
## 🛠️ 1. Tools Used
 
- 🐬 MySQL Server — stores and processes data.
- 🖥️ MySQL Workbench — write and execute SQL queries.
- 📝 Obsidian — save your notes and track progress.
 
 
***
 
## 📚 2. Study — Theory
 
### 🔹 What are `AND`, `OR`, and `NOT`?
 
These logical operators let you combine or reverse conditions in a SQL `WHERE` clause.
 
| Operator | Purpose                             | Example                                  |
| -------- | ----------------------------------- | ---------------------------------------- |
| `AND`    | All conditions must be true         | Status is `Active` AND score is above 80 |
| `OR`     | At least one condition must be true | Region is `North` OR region is `West`    |
| `NOT`    | Reverses a condition                | NOT status is `Completed`                |
 
### 🟢 A. `AND` operator
 
Use `AND` when a record must satisfy every condition.
 
```
SELECT *
FROM training_applicants
WHERE assessment_score >= 80
  AND experience_years >= 1;
```
 
Meaning: Return applicants who scored at least 80 and have at least one year of experience.
 
### 🔵 B. `OR` operator
 
Use `OR` when a record can satisfy either condition.
 
```
SELECT *
FROM training_applicants
WHERE preferred_shift = 'Morning'
   OR preferred_shift = 'Evening';
```
 
Meaning: Return applicants who prefer either the morning or evening shift.
 
### 🟠 C. `NOT` operator
 
Use `NOT` to reverse a condition.
 
```
SELECT *
FROM training_applicants
WHERE NOT application_status = 'Rejected';
```
 
Meaning: Return applicants whose status is not `Rejected`. Be aware that rows with `NULL` status will not appear in this result.
 
An equivalent form for this particular condition is:
 
```
SELECT *
FROM training_applicants
WHERE application_status <> 'Rejected';
```
 
### 🧠 D. Combining multiple operators
 
You can combine `AND`, `OR`, and `NOT` in one query.
 
```
SELECT *
FROM training_applicants
WHERE assessment_score >= 75
  AND (
	  preferred_shift = 'Morning'
	  OR preferred_shift = 'Evening'
  )
  AND NOT application_status = 'Rejected';
```
 
This returns applicants who meet all of these requirements:
 
- Score is at least 75.
- Preferred shift is Morning or Evening.
- Application status is not Rejected.
 
 
Important: Use parentheses to make the intended logic clear. SQL evaluates `AND` before `OR`, so parentheses can change the result.
 
### ⚠️ E. Common mistakes
 
- Using `AND` when you mean `OR`.
- Forgetting parentheses when mixing operators.
- Using `= NULL` instead of `IS NULL`.
- Assuming `NOT` includes rows with `NULL` values. SQL's treatment of `NULL` requires special care.

## 📚 2. Study — Theory
 
### 🔹 What is `UPDATE` in SQL?
 
The `UPDATE` statement modifies existing values in one or more rows of a database table.
 
For example, a data engineer might need to correct a delivery status, update a product's storage location, or mark a data processing job as completed.
 
Basic syntax:
 
```
UPDATE table_name
SET column_name = new_value
WHERE condition;
```
 
- `UPDATE` — specifies the table to modify.
- `SET` — defines the new value.
- `WHERE` — identifies the rows to modify.
 
 
### 🟢 A. Update one record
 
Suppose a warehouse changes the storage location of a product.
 
```
UPDATE warehouse_bins
SET bin_location = 'B-204'
WHERE bin_id = 101;
```
 
Only the row with `bin_id = 101` is updated, assuming `bin_id` uniquely identifies that row.
 
### 🔵 B. Update multiple columns
 
You can modify several columns in one statement.
 
```
UPDATE warehouse_bins
SET bin_location = 'C-105',
	bin_status = 'Occupied'
WHERE bin_id = 102;
```
 
Both values change for the matching row.
 
### 🟠 C. Update multiple records
 
A single `UPDATE` can modify multiple rows.
 
```
UPDATE warehouse_bins
SET bin_status = 'Inspection Required'
WHERE last_inspection_date < '2026-01-01';
```
 
Every row that satisfies the condition receives the new status.
 
### 🟣 D. Update with multiple conditions
 
Logical operators can be used in an `UPDATE` statement.
 
```
UPDATE warehouse_bins
SET bin_status = 'Priority Inspection'
WHERE bin_status = 'Damaged'
  AND zone_name = 'Cold Storage';
```
 
Only damaged bins in the Cold Storage zone are updated.
 
### 🔴 E. Update using an expression
 
You can calculate a new value using the existing value.
 
```
UPDATE warehouse_bins
SET inspection_count = inspection_count + 1
WHERE bin_id = 103;
```
 
This increases the inspection count by one for the matching row.
 
### ⚠️ F. Why `WHERE` is important
 
Compare these statements:
 
```
-- Updates only the matching row
UPDATE warehouse_bins
SET bin_status = 'Available'
WHERE bin_id = 101;
```
 
```
-- Updates every row in the table
UPDATE warehouse_bins
SET bin_status = 'Available';
```
 
Without `WHERE`, MySQL updates all rows in the table. Before executing an update, verify the target records with a `SELECT` query.
 
```
SELECT *
FROM warehouse_bins
WHERE bin_id = 101;
```
 
### 🛡️ G. Safer updates with transactions
 
For important changes, a transaction lets you review the result before committing it.
 
```
START TRANSACTION;
UPDATE warehouse_bins
SET bin_status = 'Available'
WHERE bin_id = 101;
SELECT *
FROM warehouse_bins
WHERE bin_id = 101;
-- Keep the change:
COMMIT;
-- Or, instead of COMMIT, undo it:
-- ROLLBACK;
```
 
Use `COMMIT` to save the transaction or `ROLLBACK` to undo its uncommitted changes. Transaction behavior depends on the table's storage engine; InnoDB supports transactions.

## 📚 2. Study — Theory

### 🔹 What is `DELETE` in SQL?

The `DELETE` statement removes existing rows from a table. You can remove selected rows using `WHERE` or remove all rows by omitting the condition.

Basic syntax:

```
DELETE FROM table_name
WHERE condition;
```

### 🟢 A. Delete a specific record

For example, remove an expired API session using its unique ID.

```
DELETE FROM api_session_registry
WHERE session_id = 501;
```

Only the row matching `session_id = 501` is deleted.

### 🔵 B. Delete multiple records

You can delete every row that matches a condition.

```
DELETE FROM api_session_registry
WHERE session_status = 'Expired';
```

This removes all sessions whose status is `Expired`.

### 🟠 C. Delete using multiple conditions

Logical operators help you select the exact records to delete.

```
DELETE FROM api_session_registry
WHERE session_status = 'Expired'
  AND environment = 'Testing';
```

Only expired sessions in the Testing environment are removed.

### 🔴 D. What happens without `WHERE`?

```
DELETE FROM api_session_registry;
```

This deletes all rows in the table but leaves the table structure in place.

> ⚠️ Always check the target rows using `SELECT` before executing a `DELETE` statement.

```
SELECT *
FROM api_session_registry
WHERE session_status = 'Expired';
```

### 🟣 E. Difference between `DELETE`, `TRUNCATE`, and `DROP`

|Command|Purpose|Table structure|
|---|---|---|
|`DELETE`|Removes selected rows or all rows|Retained|
|`TRUNCATE TABLE`|Removes all rows efficiently|Retained|
|`DROP TABLE`|Removes the table itself|Removed|

Important differences:

- `DELETE` supports a `WHERE` condition; `TRUNCATE` does not.
    
- In MySQL, `TRUNCATE TABLE` is a DDL operation and generally causes an implicit commit.
    
- `DROP TABLE` removes both the table definition and its data.
    
- `DELETE` can often be rolled back if executed inside a transaction on a transactional engine such as InnoDB and not yet committed. Do not assume `TRUNCATE` or `DROP` can be undone the same way.
    

### 🛡️ F. Safer deletion with transactions

```
START TRANSACTION;

DELETE FROM api_session_registry
WHERE session_id = 501;

SELECT *
FROM api_session_registry;

-- Save the deletion:
COMMIT;

-- Alternatively, before COMMIT, undo it:
-- ROLLBACK;
```

A `SELECT` without a `WHERE` condition shows all remaining rows. For more reliable verification, query the deleted ID directly to confirm that it no longer appears.

## 📚 2. Study — Theory

### 🔹 What are SQL constraints?

SQL constraints are rules applied to table columns or tables to help maintain accurate and consistent data. They prevent certain invalid values or relationships from being stored.

For example, a warehouse system should not allow two storage locations to share the same unique identifier, and a shipment record should not refer to a carrier that does not exist when a foreign key enforces that relationship.

### 🟢 A. `PRIMARY KEY`

A primary key uniquely identifies each row in a table. It cannot contain duplicate values or `NULL`.

```
CREATE TABLE shipping_carriers (
    carrier_id INT PRIMARY KEY,
    carrier_name VARCHAR(100)
);
```

Here, `carrier_id` uniquely identifies each carrier.

### 🔵 B. `FOREIGN KEY`

A foreign key enforces a relationship between a column in one table and a referenced key in another table.

```
CREATE TABLE carrier_shipments (
    shipment_id INT PRIMARY KEY,
    carrier_id INT,
    FOREIGN KEY (carrier_id)
        REFERENCES shipping_carriers(carrier_id)
);
```

A shipment's `carrier_id` must match an existing carrier ID, unless the foreign-key column allows `NULL`.

### 🟠 C. `UNIQUE`

A `UNIQUE` constraint prevents duplicate values in a column or combination of columns.

```
CREATE TABLE api_service_registry (
    service_id INT PRIMARY KEY,
    endpoint_url VARCHAR(200) UNIQUE
);
```

Two rows cannot have the same non-`NULL` endpoint URL. In MySQL, a unique index can permit multiple `NULL` values.

### 🟣 D. `NOT NULL`

`NOT NULL` requires a column to contain a value rather than `NULL`.

```
CREATE TABLE sensor_registry (
    sensor_id INT PRIMARY KEY,
    sensor_name VARCHAR(100) NOT NULL
);
```

Every sensor record must have a non-`NULL` name.

### 🔴 E. `CHECK`

A `CHECK` constraint enforces a condition on the values stored in a row.

```
CREATE TABLE temperature_readings (
    reading_id INT PRIMARY KEY,
    temperature_c DECIMAL(5,2),
    CHECK (temperature_c >= -100 AND temperature_c <= 100)
);
```

This restricts the temperature to the specified range. MySQL enforces `CHECK` constraints in MySQL 8.0.16 and later.

### ⚪ F. `DEFAULT`

A `DEFAULT` constraint supplies a value when an `INSERT` omits that column or uses the `DEFAULT` keyword.

```
CREATE TABLE data_job_registry (
    job_id INT PRIMARY KEY,
    job_name VARCHAR(100) NOT NULL,
    job_status VARCHAR(20) DEFAULT 'Pending'
);
```

If an insert omits `job_status`, MySQL uses `Pending`.

### 📊 G. Constraint summary

|Constraint|Purpose|
|---|---|
|`PRIMARY KEY`|Uniquely identifies each row|
|`FOREIGN KEY`|Enforces valid relationships|
|`UNIQUE`|Prevents duplicate non-`NULL` key values|
|`NOT NULL`|Prevents missing values|
|`CHECK`|Enforces a condition on values|
|`DEFAULT`|Supplies a default value when applicable|

### 🧠 H. Why constraints matter in Data Engineering

- They prevent invalid records from entering important tables.
    
- They enforce key relationships between datasets.
    
- They support data quality and consistency.
    
- They help detect problems at the point of insertion or modification.
    

Important: Constraints do not replace all data-quality checks. For example, a foreign key cannot prove that a carrier's real-world details are correct; it only enforces the configured database relationship.

## 📚 2. Study — Theory

### 🔹 What is `ALTER TABLE`?

`ALTER TABLE` changes the structure of an existing table without requiring you to recreate the entire table.

As a Data Engineer, you might need to add a column to track a new attribute, increase a column's permitted length, rename a column, or remove an obsolete field.

### 🟢 A. `ADD COLUMN` — Add a new column

Suppose a logistics table needs a new column to store the delivery priority.

```
ALTER TABLE freight_orders
ADD COLUMN priority_level VARCHAR(20);
```

This adds `priority_level` to the existing table. Existing rows receive `NULL` in that column if no default value is specified and the column allows it.

You can also add a column with a default:

```
ALTER TABLE freight_orders
ADD COLUMN review_status VARCHAR(20) DEFAULT 'Pending';
```

### 🔵 B. `MODIFY COLUMN` — Change a column definition

Use `MODIFY COLUMN` to change a column's data type or attributes without renaming it.

```
ALTER TABLE freight_orders
MODIFY COLUMN priority_level VARCHAR(40);
```

This increases the permitted length of the column.

Important: Check existing values before narrowing a column or adding restrictive attributes. Some changes can fail or cause data loss, depending on the data and MySQL configuration.

### 🟠 C. `CHANGE COLUMN` — Rename or redefine a column

In MySQL, `CHANGE COLUMN` can rename a column and specify its new definition.

```
ALTER TABLE freight_orders
CHANGE COLUMN priority_level delivery_priority VARCHAR(40);
```

The new column name is `delivery_priority`, and its data type remains `VARCHAR(40)`.

Unlike some database systems, MySQL's `CHANGE COLUMN` syntax requires the new column definition to be included.

### 🟣 D. `RENAME COLUMN` — Rename a column

For a rename without changing the data type, MySQL also supports:

```
ALTER TABLE freight_orders
RENAME COLUMN delivery_priority TO priority_level;
```

This changes the column name but keeps its existing definition.

### 🔴 E. `DROP COLUMN` — Remove a column

Use `DROP COLUMN` to remove a field that is no longer needed.

```
ALTER TABLE freight_orders
DROP COLUMN priority_level;
```

> ⚠️ Dropping a column removes its stored values. Confirm that the column is not required by reports, applications, views, or data pipelines before removing it.

### ⚪ F. `RENAME TABLE` — Rename an entire table

```
RENAME TABLE freight_orders
TO regional_freight_orders;
```

This changes the table's name, not its columns.

### 🧠 G. `ALTER TABLE` vs. `UPDATE`

|Statement|Purpose|Example|
|---|---|---|
|`ALTER TABLE`|Changes the table structure|Add a column|
|`UPDATE`|Changes existing row values|Correct an order status|
|`DELETE`|Removes rows|Remove an obsolete order|
|`DROP TABLE`|Removes the table itself|Remove a dedicated practice table|

Remember: `ALTER TABLE` is a DDL statement. Many MySQL DDL operations cause implicit commits, so do not assume that `ROLLBACK` will undo a schema change.

## 🛠️ 1. Tools Used

- 📝 Obsidian — save notes and track learning progress.

## 📚 2. Study — Theory

### 🔹 What is `ORDER BY`?

The `ORDER BY` clause sorts the rows returned by a SQL query according to one or more columns or expressions.

Data Engineers use it to arrange records by timestamp, rank processing results, sort reports, and make query output easier to inspect.

Basic syntax:

```
SELECT column_name
FROM table_name
ORDER BY column_name ASC;
```

- `ORDER BY` specifies the sorting rule.
    
- `ASC` sorts in ascending order.
    
- `DESC` sorts in descending order.
    

### 🟢 A. Ascending order — `ASC`

Ascending order sorts values from lowest to highest for numbers, earliest to latest for dates, and according to the applicable collation for text.

```
SELECT *
FROM sensor_reading_archive
ORDER BY reading_value ASC;
```

Example numeric order: `12, 25, 40, 85`.

Note: `ASC` is the default direction in MySQL, so it can be omitted.

### 🔵 B. Descending order — `DESC`

Descending order sorts values from highest to lowest.

```
SELECT *
FROM sensor_reading_archive
ORDER BY reading_value DESC;
```

Example numeric order: `85, 40, 25, 12`.

This is useful when you want to see the highest readings or largest values first.

### 🟠 C. Sort using multiple columns

You can sort by one column and use another column to break ties.

```
SELECT *
FROM sensor_reading_archive
ORDER BY station_code ASC,
         reading_value DESC;
```

The results are sorted by station code first. Within each station, readings are sorted from highest to lowest.

### 🟣 D. Sort by a calculated expression

`ORDER BY` can use an expression instead of a stored column.

```
SELECT
    shipment_code,
    base_fee,
    fuel_surcharge,
    base_fee + fuel_surcharge AS total_fee
FROM freight_charge_log
ORDER BY base_fee + fuel_surcharge DESC;
```

This places the highest calculated fees first.

### 🔴 E. Sort using a column alias

You can sort by an alias defined in the `SELECT` list.

```
SELECT
    shipment_code,
    base_fee + fuel_surcharge AS total_fee
FROM freight_charge_log
ORDER BY total_fee DESC;
```

This can make queries easier to read.

### ⚪ F. Sort date and time values

Date and time columns can be sorted chronologically.

```
SELECT *
FROM system_event_archive
ORDER BY event_timestamp DESC;
```

This places the newest events first, assuming `event_timestamp` stores valid date-time values.

### 🧠 G. Sort `NULL` values

MySQL sorts `NULL` values before non-`NULL` values in ascending order and after non-`NULL` values in descending order.

To place missing values last in either direction, you can use an expression:

```
SELECT *
FROM sensor_reading_archive
ORDER BY
    reading_value IS NULL,
    reading_value ASC;
```

This sorts non-`NULL` readings first and places `NULL` readings last.

### ⚠️ H. Important rules

- `ORDER BY` sorts the query result; it does not permanently reorder the underlying table.
    
- Without `ORDER BY`, row order is not guaranteed.
    
- If multiple rows share the same sort value, their relative order is not guaranteed unless you add a tie-breaker.
    
- Sorting can require additional work for large datasets, so appropriate indexes and query plans matter.

## 📚 2. Study — Theory

### 🔹 What is `DISTINCT`?

`DISTINCT` removes duplicate rows from the result of a `SELECT` query. It does not delete or change the original data in your table.

Suppose a delivery system stores these regions:

|Region|
|---|
|North|
|South|
|North|
|East|
|South|

Query:

```
SELECT DISTINCT region
FROM delivery_records;
```

Result:

|region|
|---|
|North|
|South|
|East|

Each region appears once in the query result.

### 🔹 What is a column alias?

A column alias gives a column or calculated expression a temporary, more readable name in a query result.

```
SELECT
    region AS delivery_region
FROM delivery_records;
```

Here, `delivery_region` is the alias. It changes the displayed column heading, not the actual table structure or stored column name.

### 🔹 `DISTINCT` with multiple columns

When you specify multiple columns, SQL returns unique combinations of their values.

```
SELECT DISTINCT region, delivery_status
FROM delivery_records;
```

For example, `North + Delivered` and `North + Pending` are two different combinations. Each combination appears once, even if it occurs many times in the table.

### 🔹 Using aliases with calculations

Aliases also make calculated columns easier to understand.

```
SELECT
    storage_gb,
    monthly_rate,
    storage_gb * monthly_rate AS estimated_monthly_cost
FROM cloud_storage_usage;
```

The expression calculates the estimated cost for each row and displays the result under `estimated_monthly_cost`.

### ⚠️ Important Rules

- `DISTINCT` applies to all selected columns together, not just the first column.
    
- `DISTINCT` does not modify the underlying table.
    
- An alias exists for the query result; it does not rename the physical column.
    
- Use `AS` to make aliases easy to recognise.
    
- Avoid ambiguous aliases such as `value` or `data` when a meaningful name is possible.
    
- `DISTINCT` can require extra processing on large datasets, so use it when uniqueness is genuinely needed.

## 📚 2. Study — Theory

### 🔹 What is `IN`?

The `IN` operator checks whether a value matches any value in a specified list.

```
SELECT *
FROM equipment_registry
WHERE equipment_type IN ('Scanner', 'Router', 'Gateway');
```

This returns records whose `equipment_type` is `Scanner`, `Router`, or `Gateway`.

The query is a convenient alternative to writing several `OR` conditions:

```
WHERE equipment_type = 'Scanner'
   OR equipment_type = 'Router'
   OR equipment_type = 'Gateway';
```

When to use it: Filtering selected categories, regions, status codes, source systems, or identifiers.

### 🔹 What is `NOT IN`?

`NOT IN` returns values that do not match the listed values.

```
SELECT *
FROM equipment_registry
WHERE equipment_type NOT IN ('Scanner', 'Router');
```

This excludes scanners and routers. Be careful when the list contains `NULL`: SQL's three-valued logic can cause `NOT IN` to return no rows or fewer rows than expected. Handle missing values separately when necessary.

### 🔹 What is `BETWEEN`?

`BETWEEN` filters values within an inclusive range. Both the lower and upper boundaries are included.

```
SELECT *
FROM sensor_measurements
WHERE reading_value BETWEEN 20 AND 40;
```

This includes values equal to `20` and `40`, as well as values between them.

You can use `BETWEEN` with numbers, dates, and other comparable values.

For dates, remember that `BETWEEN` includes both endpoints. If a column is a `DATETIME`, a condition ending at `'2026-10-21'` means midnight at the start of that date, not the entire day. For full-day timestamp filtering, a half-open range is often safer:

```
WHERE event_time >= '2026-10-21'
  AND event_time <  '2026-10-22';
```

### 🔹 What is `NULL`?

`NULL` represents a missing, unknown, or unavailable value. It is not the same as:

- `0` — a numeric value.
    
- `''` — an empty string.
    
- `'NULL'` — ordinary text containing the word NULL.
    

Use `IS NULL` to find missing values:

```
SELECT *
FROM shipment_registry
WHERE delivery_date IS NULL;
```

Use `IS NOT NULL` to find values that are present:

```
SELECT *
FROM shipment_registry
WHERE delivery_date IS NOT NULL;
```

Do not use `= NULL` or `<> NULL` to test missing values. These comparisons evaluate to unknown rather than producing the expected match.

### 🔹 Combining the operators

You can combine `IN`, `BETWEEN`, and `IS NULL` with other conditions.

```
SELECT *
FROM shipment_registry
WHERE shipment_status IN ('Delayed', 'On Hold')
  AND weight_kg BETWEEN 5 AND 25;
```

This returns shipments that meet both conditions.

## 📚 2. Study — Theory

### 🔹 What are aggregate functions?

Aggregate functions perform calculations across multiple rows and return a summary value. They are useful when a data engineer needs to understand the overall size, cost, volume, or quality of a dataset.

For example, instead of examining thousands of transaction records individually, you can use aggregate functions to calculate the total transaction value or average processing time.

### 🔢 1. `COUNT()` — Count Records

`COUNT()` counts rows or non-`NULL` values in a column.

```
SELECT COUNT(*) AS total_records
FROM sensor_archive;
```

- `COUNT(*)` counts all rows, including rows containing `NULL`.
    
- `COUNT(column_name)` counts only rows where that column is not `NULL`.
    
- `COUNT(DISTINCT column_name)` counts unique, non-`NULL` values.
    

### 💰 2. `SUM()` — Calculate a Total

`SUM()` adds numeric values in a column.

```
SELECT SUM(storage_cost) AS total_storage_cost
FROM cloud_billing;
```

This calculates the total storage cost across the selected records.

### 📊 3. `AVG()` — Calculate an Average

`AVG()` calculates the arithmetic mean of non-`NULL` numeric values.

```
SELECT AVG(processing_seconds) AS average_processing_seconds
FROM job_history;
```

If the processing times are `10`, `20`, and `30`, the average is `20`.

Important: `AVG()` ignores `NULL` values. A missing value is not treated as zero.

### 📉 4. `MIN()` — Find the Minimum

`MIN()` returns the smallest value.

```
SELECT MIN(response_time_ms) AS fastest_response_ms
FROM api_monitoring;
```

This identifies the smallest recorded response time.

### 📈 5. `MAX()` — Find the Maximum

`MAX()` returns the largest value.

```
SELECT MAX(response_time_ms) AS slowest_response_ms
FROM api_monitoring;
```

This identifies the largest recorded response time.

### ⚠️ Important Rules

- Aggregate functions summarise data; they do not modify the original rows.
    
- `COUNT(*)` includes every row.
    
- `COUNT(column_name)`, `SUM()`, `AVG()`, `MIN()`, and `MAX()` ignore `NULL` values in the relevant column.
    
- `SUM()` and `AVG()` operate on numeric values.
    
- If there are no matching rows, `COUNT(*)` returns `0`, while `SUM()` and `AVG()` generally return `NULL`. `MIN()` and `MAX()` also return `NULL` when no non-`NULL` values are available.
    
- Aggregate functions can be used alongside filters such as `WHERE`.
    
- Use meaningful aliases to make summary reports easier to understand.

## 📚 2. Study — Theory

### 🔹 What is `GROUP BY`?

`GROUP BY` combines rows that share the same value in one or more columns into groups. You can then use aggregate functions to calculate a summary for each group.

For example, a streaming platform may record thousands of events from different applications. Instead of counting every event individually, you can count the events generated by each application.

```
SELECT
    application_name,
    COUNT(*) AS total_events
FROM application_event_log
GROUP BY application_name;
```

The result contains one row per application name, with its event count.

### 🔹 How does `GROUP BY` work?

Suppose a dataset contains these records:

|Application|Events|
|---|---|
|Billing|100|
|Search|200|
|Billing|150|
|Search|50|
|Reports|80|

Grouping by application produces:

|Application|Total events|
|---|---|
|Billing|250|
|Search|250|
|Reports|80|

The original records remain unchanged. The query creates a summary result.

### 🔹 `GROUP BY` with aggregate functions

|Function|Purpose|
|---|---|
|`COUNT(*)`|Count rows in each group|
|`SUM(column)`|Calculate the total for each group|
|`AVG(column)`|Calculate the average non-`NULL` value|
|`MIN(column)`|Find the minimum value in each group|
|`MAX(column)`|Find the maximum value in each group|

Example:

```
SELECT
    application_name,
    COUNT(*) AS total_events,
    SUM(event_size_kb) AS total_size_kb,
    AVG(event_size_kb) AS average_size_kb
FROM application_event_log
GROUP BY application_name;
```

### 🔹 Grouping by multiple columns

You can group by two or more columns to create more detailed summaries.

```
SELECT
    cloud_region,
    resource_type,
    SUM(monthly_cost) AS total_cost
FROM infrastructure_costs
GROUP BY cloud_region, resource_type;
```

Each unique combination of `cloud_region` and `resource_type` produces a separate group.

### 🔹 `WHERE` before grouping

Use `WHERE` to filter individual records before `GROUP BY` calculates summaries.

```
SELECT
    application_name,
    COUNT(*) AS failed_events
FROM application_event_log
WHERE event_status = 'Failed'
GROUP BY application_name;
```

Only failed events enter the grouping process.

### 🔹 Important rules

- Every selected column that is not aggregated should generally appear in `GROUP BY` when using standard grouping rules.
    
- `GROUP BY` does not modify the source table.
    
- `NULL` values in a grouping column are collected into one group.
    
- Aggregate functions such as `SUM()` and `AVG()` ignore `NULL` values in the aggregated column.
    
- Use `ORDER BY` when you need a guaranteed output order.
    
- In MySQL, `ONLY_FULL_GROUP_BY` is commonly enabled. Avoid selecting unrelated, ungrouped columns because MySQL may reject the query or the result may be ambiguous.
    
- `GROUP BY` and `DISTINCT` are not interchangeable: `DISTINCT` removes duplicate result rows, while `GROUP BY` is commonly used to calculate summaries per group.

# 📘 Day 17: SQL `HAVING` Clause

🎯 Goal: Learn to filter grouped data and build a real-world e-commerce delivery performance report using MySQL.

💻 Study ratio: 20% essential theory + 80% practical coding.

## 📚 1. Important theory

📖 The `HAVING` clause filters groups created by `GROUP BY`, often using aggregate functions such as `COUNT()`, `SUM()`, `AVG()`, and `MAX()`.

💡 Syntax:

```
SELECT column_name, COUNT(*) AS total
FROM table_name
GROUP BY column_name
HAVING COUNT(*) > 5;
```

🔍 `WHERE` vs. `HAVING`:

|Feature|`WHERE`|`HAVING`|
|---|---|---|
|🎯 Purpose|Filters individual rows|Filters groups|
|⚙️ Processing|Before grouping|After grouping|
|💻 Example|`WHERE status = 'Late'`|`HAVING COUNT(*) > 5`|

## 🧩 3. Solved SQL examples

### 🔹 Example 1: Find partners with more than five orders

```
SELECT
    delivery_partner,
    COUNT(*) AS total_orders
FROM delivery_orders
GROUP BY delivery_partner
HAVING COUNT(*) > 5;
```

📊 Expected output:

|delivery_partner|total_orders|
|---|---|
|SwiftShip|6|
|QuickMove|6|
|ReliableExpress|6|

💡 Explanation: `GROUP BY` creates one group per partner, and `HAVING` retains groups with more than five orders.

### 🔹 Example 2: Find partners with an average delivery time above three days

```
SELECT
    delivery_partner,
    ROUND(AVG(delivery_days), 2) AS avg_delivery_days
FROM delivery_orders
GROUP BY delivery_partner
HAVING AVG(delivery_days) > 3;
```

📊 Expected output:

|delivery_partner|avg_delivery_days|
|---|---|
|SwiftShip|3.17|

💡 Explanation: `AVG()` calculates the average for each partner, and `HAVING` filters averages greater than three.

### 🔹 Example 3: Find partners with at least two late orders

```
SELECT
    delivery_partner,
    COUNT(*) AS late_orders
FROM delivery_orders
WHERE delivery_status = 'Late'
GROUP BY delivery_partner
HAVING COUNT(*) >= 2;
```

📊 Expected output:

|delivery_partner|late_orders|
|---|---|
|SwiftShip|2|

💡 Explanation: `WHERE` first selects late orders, and `HAVING` keeps partners with at least two of them.

### 🔹 Example 4: Find partners with zero late deliveries

```
SELECT
    delivery_partner,
    SUM(
        CASE WHEN delivery_status = 'Late'
             THEN 1 ELSE 0 END
    ) AS late_orders
FROM delivery_orders
GROUP BY delivery_partner
HAVING SUM(
    CASE WHEN delivery_status = 'Late'
         THEN 1 ELSE 0 END
) = 0;
```

📊 Expected output:

|delivery_partner|late_orders|
|---|---|
|ReliableExpress|0|

💡 Explanation: `CASE` returns 1 for late orders and 0 for other orders; `SUM()` counts the late orders.

## 🏢 5. Real-world mini project: Delivery Performance Monitoring

🎯 Business problem: An e-commerce company wants to identify delivery partners whose late-delivery rates exceed 10%.

🛠️ What we build: A report showing total orders, late orders, and late-delivery percentage for each partner.

📌 Training requirement: Only consider partners with at least five orders; a production report might require 50 or more orders.

### 💻 Step 1: Run the complete project query

```
SELECT
    delivery_partner,
    COUNT(*) AS total_orders,
    SUM(
        CASE
            WHEN delivery_status = 'Late' THEN 1
            ELSE 0
        END
    ) AS late_orders,
    ROUND(
        100.0 * SUM(
            CASE
                WHEN delivery_status = 'Late' THEN 1
                ELSE 0
            END
        ) / COUNT(*),
        2
    ) AS late_rate_percent
FROM delivery_orders
GROUP BY delivery_partner
HAVING COUNT(*) >= 5
   AND 100.0 * SUM(
       CASE
           WHEN delivery_status = 'Late' THEN 1
           ELSE 0
       END
   ) / COUNT(*) > 10
ORDER BY late_rate_percent DESC;
```

📊 Step 2: Expected output

|delivery_partner|total_orders|late_orders|late_rate_percent|
|---|---|---|---|
|SwiftShip|6|2|33.33|
|QuickMove|6|1|16.67|

🔍 Step 3: Understand the solution

- 🗂️ `GROUP BY` groups orders by delivery partner.
    
- 🔢 `COUNT()` calculates the total number of orders.
    
- 🧮 `SUM(CASE...)` counts late orders.
    
- 📈 The percentage formula calculates the late-delivery rate.
    
- 🎯 `HAVING` keeps only partners with a rate above 10% and at least five orders.
    
- ↕️ `ORDER BY` places the highest late-delivery rate first.
    

✅ Business result: SwiftShip and QuickMove need investigation because their late-delivery rates exceed the target.

💡 Data Engineering connection: This type of query can be part of a scheduled reporting pipeline that transforms delivery records into operational metrics for a dashboard.
